## Public-Key Cryptosystems Based on the Discrete Logarithm Problem

Public-key cryptography relies on the existence of **trapdoor one-way functions**—mathematical operations that are computationally efficient to evaluate in the forward direction, but computationally infeasible to invert without specific trapdoor information. Alongside integer factorization (RSA), the **Discrete Logarithm Problem (DLP)** forms the theoretical and practical foundation of modern asymmetric cryptography, key establishment protocols, and digital signature standards.

```
                    ┌────────────────────────────────────────────────────────┐
                    │               Discrete Logarithm Problem               │
                    │               Given (g, p, y), find x in:             │
                    │                    y ≡ gˣ (mod p)                      │
                    └───────────────────────────┬────────────────────────────┘
                                                │
                       ┌────────────────────────┴────────────────────────┐
                       ▼                                                 ▼
        ┌─────────────────────────────┐                   ┌─────────────────────────────┐
        │  Diffie-Hellman Key Exchange│                   │ ElGamal Asymmetric Crypto   │
        │  • Shared Secret Agreement  │                   │ • Public-Key Encryption     │
        │  • Forward Secrecy (DHE)    │                   │ • Digital Signatures / DSA  │
        │  • CDH / DDH Assumptions    │                   │ • Homomorphic Properties    │
        └─────────────────────────────┘                   └─────────────────────────────┘
```

### 1. The Discrete Logarithm Problem (DLP)

#### Mathematical Definition
Let $G$ be a finite cyclic group of order $n$ generated by an element $g \in G$. For any element $y \in G$, the discrete logarithm of $y$ to the base $g$ is the unique integer $x \in \mathbb{Z}_n$ such that:

$$g^x = y \quad (\text{in } G)$$

In the classical multiplicative group of integers modulo a prime $p$, denoted $\mathbb{Z}_p^* = \{1, 2, \dots, p-1\}$:

$$y \equiv g^x \pmod p$$

- **Forward Direction (Modular Exponentiation):** Given base $g$, exponent $x$, and modulus $p$, computing $y \equiv g^x \pmod p$ is achievable in polynomial time $O(\log x \cdot \log^2 p)$ using repeated squaring (square-and-multiply).
- **Inverse Direction (Discrete Logarithm):** Given base $g$, result $y$, and modulus $p$, finding $x = \log_g y$ has no known polynomial-time classical algorithm for properly selected groups.

#### Why the Discrete Logarithm Problem is Fundamental
1. **Asymmetric Trapdoor Primitive:** DLP provides a clean algebraic framework where a private exponent $x$ generates a public group element $y = g^x$.
2. **Diversity from Factorization:** While RSA relies on the difficulty of splitting composite $N = pq$, DLP operates over prime fields $\mathbb{F}_p$ or elliptic curve groups $E(\mathbb{F}_p)$, providing independent mathematical assumptions.
3. **Foundation for Non-Interactive Proofs & Protocols:** DLP and its decisional variants are the basis for zero-knowledge proofs (Schnorr protocols), threshold cryptosystems, verifiable secret sharing, and blind signatures.

### 2. Diffie-Hellman Key Exchange (DHKE)

Introduced by Whitfield Diffie and Martin Hellman in 1976, DHKE was the first published method allowing two parties to establish a shared cryptographic secret over an unencrypted, adversarial communication channel without transmitting the secret itself.

```
       Alice (Private: a)                                  Bob (Private: b)
  ─────────────────────────────                       ───────────────────────────
   Public Parameters: (p, g)                           Public Parameters: (p, g)
   
   Computes: A = gᵃ mod p          ─── Public A ───►   Computes: B = gᵇ mod p
                                   ◄─── Public B ───
   
   Computes Shared Secret:                             Computes Shared Secret:
   K = Bᵃ mod p                                        K = Aᵇ mod p
     = (gᵇ)ᵃ = gᵃᵇ mod p                                 = (gᵃ)ᵇ = gᵃᵇ mod p
```

#### Protocol Mechanics
1. **Public Domain Parameters:** A large prime $p$ and a generator $g \in \mathbb{Z}_p^*$.
2. **Key Generation:**
   - Alice selects a private key $a \in_R [2, p-2]$ and transmits public key $A = g^a \bmod p$.
   - Bob selects a private key $b \in_R [2, p-2]$ and transmits public key $B = g^b \bmod p$.
3. **Shared Secret Derivation:**
   - Alice computes: $K_A = B^a \equiv (g^b)^a \equiv g^{ab} \pmod p$.
   - Bob computes: $K_B = A^b \equiv (g^a)^b \equiv g^{ab} \pmod p$.
   - Both parties compute the identical secret $K = g^{ab} \pmod p$.
   - The raw group element $K$ is passed through a Key Derivation Function (e.g., HKDF-SHA256) to produce symmetric session keys (AES-GCM / ChaCha20-Poly1305).

#### Computational Assumptions
- **Discrete Logarithm Problem (DLP):** Given $(g, g^a)$, computing $a$ is hard.
- **Computational Diffie-Hellman (CDH):** Given $(g, g^a, g^b)$, computing $g^{ab}$ is hard without knowledge of $a$ or $b$.
- **Decisional Diffie-Hellman (DDH):** Given $(g, g^a, g^b, T)$, distinguishing whether $T = g^{ab}$ or $T$ is a random group element is computationally indistinguishable.

#### Why Diffie-Hellman is Critical
- **Solved the Key Distribution Bottleneck:** Eliminated the historical requirement for pre-shared physical key couriers in symmetric networks.
- **Enables Perfect Forward Secrecy (PFS):** In Ephemeral Diffie-Hellman (DHE / ECDHE), new key pairs $(a, b)$ are generated per session and discarded immediately after key derivation. Compromising a server's long-term identity key does not expose past encrypted traffic.
- **Core of Modern Transport Security:** Underpins handshake security in **TLS 1.3**, **SSH-2**, **IPsec / IKEv2**, **Signal Protocol**, and **WireGuard**.

### 3. ElGamal Public-Key Cryptosystem

Proposed by Taher Elgamal in 1985, the ElGamal cryptosystem transformed the Diffie-Hellman key exchange mechanism into a full asymmetric encryption and digital signature scheme.

```
                                  ElGamal Encryption
  
   Public Key: (p, g, y = gˣ mod p)                    Private Key: x
  
   Sender (Alice):                                     Receiver (Bob):
   - Choose ephemeral random k                         - Receives (c₁, c₂)
   - Compute c₁ = gᵏ mod p                             - Computes shared mask: s = c₁ˣ mod p
   - Compute shared mask s = yᵏ mod p                  - Computes s⁻¹ mod p via EEA
   - Compute c₂ = m · s mod p                          - Recovers message: m = c₂ · s⁻¹ mod p
   
   Ciphertext: C = (c₁, c₂)
```

#### Protocol Specification
1. **Key Generation:**
   - Domain parameters: Prime $p$, generator $g$.
   - Private key: $x \in_R [2, p-2]$.
   - Public key: $y = g^x \bmod p$.
2. **Encryption:**
   - Plaintext message $m \in \mathbb{Z}_p^*$.
   - Select ephemeral random nonce $k \in_R [2, p-2]$ such that $\gcd(k, p-1) = 1$.
   - Compute ciphertext pair $(c_1, c_2)$:
     $$c_1 \equiv g^k \pmod p$$
     $$c_2 \equiv m \cdot y^k \equiv m \cdot (g^x)^k \pmod p$$
3. **Decryption:**
   - Using private key $x$, recover the shared masking factor $s = c_1^x \equiv (g^k)^x \equiv g^{kx} \pmod p$.
   - Invert $s$ using the Extended Euclidean Algorithm: $s^{-1} \equiv (c_1^x)^{-1} \pmod p$.
   - Decrypt:
     $$m \equiv c_2 \cdot (c_1^x)^{-1} \equiv (m \cdot g^{kx}) \cdot (g^{kx})^{-1} \equiv m \pmod p$$

#### Properties & Significance
1. **Probabilistic Encryption (Semantic Security):**
   - Because a fresh random ephemeral exponent $k$ is chosen for each encryption, encrypting the identical plaintext $m$ multiple times yields distinct, uncorrelated ciphertexts. This prevents codebook attacks and satisfies **IND-CPA** (Indistinguishability under Chosen-Plaintext Attack) under the Decisional Diffie-Hellman (DDH) assumption.
2. **Multiplicative Homomorphism:**
   - Given two ciphertexts $C_1 = (g^{k_1}, m_1 y^{k_1})$ and $C_2 = (g^{k_2}, m_2 y^{k_2})$, their component-wise product:
     $$C_{1 \cdot 2} = (c_{1,1} \cdot c_{2,1}, \; c_{1,2} \cdot c_{2,2}) = (g^{k_1 + k_2}, \; (m_1 m_2) y^{k_1 + k_2})$$
   - Decrypts directly to $m_1 \cdot m_2 \bmod p$. This property makes ElGamal a fundamental building block in electronic voting protocols, privacy-preserving multiparty computation (MPC), and mixnets.
3. **Precursor to Modern Signature Standards:**
   - ElGamal's signature variant led directly to the development of the **Digital Signature Algorithm (DSA)** standardized in NIST FIPS 186, and subsequently **ECDSA** and **Schnorr Signatures** (BIP-340).

### 4. Cryptanalytic Landscape & Modern Parameter Selection

The security of DLP-based cryptosystems depends on the group structure in which operations are executed:

| Group Family | Best Known Classical Attack | Complexity | NIST 128-bit Security Recommendation |
| :--- | :--- | :--- | :--- |
| **Finite Field $\mathbb{Z}_p^*$ (FFDHE / DSA)** | Index Calculus / Number Field Sieve (NFS) | Subexponential: $L_p\left[\frac{1}{3}, c\right] = \exp\left( (c + o(1))(\ln p)^{1/3} (\ln \ln p)^{2/3} \right)$ | $p \ge 3072 \text{ bits}$ (Subgroup $q \ge 256 \text{ bits}$) |
| **Elliptic Curves $E(\mathbb{F}_p)$ (ECDH / ECDSA)** | Pollard's $\rho$ / Baby-Step Giant-Step | Exponential (Generic): $\mathcal{O}(\sqrt{n}) \approx 2^{b/2}$ | 256-bit curve (e.g., Curve25519, secp256r1) |

#### Implementation & Hardening Requirements
- **Safe Prime Construction:** In finite field groups, choose $p = 2q + 1$ where $q$ is also prime (Sophie Germain prime), preventing subgroup-confinement attacks (Pohlig-Hellman).
- **Subgroup Validation:** Always verify that received public keys $A, B \in G$ satisfy $1 < A < p-1$ and $A^q \equiv 1 \pmod p$ to prevent small-subgroup confinement and invalid curve attacks.
- **Constant-Time Modular Arithmetic:** Modular exponentiation ($g^x \bmod p$) must execute in constant time to eliminate side-channel timing leaks and power analysis (SPA/DPA).
- **Quantum Threat Horizon:** Both the Discrete Logarithm Problem and Integer Factorization are solvable in polynomial time $O((\log p)^3)$ via **Shor's Algorithm** on cryptographically relevant quantum computers (CRQCs), driving the ongoing transition to NIST Post-Quantum Cryptography (ML-KEM / ML-DSA).
